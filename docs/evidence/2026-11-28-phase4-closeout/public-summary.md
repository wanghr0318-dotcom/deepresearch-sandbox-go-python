## 能从哪个版本继续

```text
worker 写文件 → Gateway 发布本次工作区版本
worker 保存消息、步骤、稳定调用号 → Gateway 保存并校验内容对象，再保存 manifest
→ PG 锁内核对 task、current attempt 和写权 → 提交 checkpoint、摘要和恢复游标
→ 继任 attempt 按 PG 选中的摘要恢复 → 校验文件 → 下一次工具调用
```

已提交的 checkpoint 重试会取用原 manifest。历史 checkpoint 缺少 manifest 时沿用原宿主工作区，其跨机可移植性无法追溯保证。继任 attempt 尚无 checkpoint 时清除未提交工作区，从原任务输入开始。[装配与兼容路径](../../../internal/app/workspace_recovery.go) · [PG 事务](../../../internal/persistence/postgres/runner.go)

## 租约与控制链路

在本次 K3s v1.34.13+k3s1 环境，丢失既有 pods/exec 控制流可先触发 control_lost。PG 撤销旧 attempt 写权，替代环境的准入需满足旧环境已停止或已完成持久化隔离。运行时仍受旧环境收敛、恢复槽和 Pod 就绪影响，120 秒没有提供业务恢复时间上界。

20、40、45、50、70、90 秒各三轮，前四档 12 轮原主续跑；其余 6 轮中 4 轮在原租约到期前取得新授权，2 轮有到期隔离记录。18 轮分别 4/4，观测的 PG 授权重叠均为 0 秒。另有 60、108、132 秒及三次短断，每种三轮，慢模型回包单列三轮。这组 12 轮中，03-132 的评分器因 grade_no_output 中止；07-132 缺少可评的工具结果，两轮的用例得分均留空。三个慢模型对照分别等待 145.0006、145.0006、145.0007 秒，均由同一身份完成。有续租的 120 秒租期覆盖了无业务消息的等待。租约起点和施加断链的时刻是两种口径。每轮的行为、评分、缺测值见附表。[逐轮观测](trials.json)

自然 worker 在三个 60 秒控制分区轮次撤权后仍短暂存活，历史日志中找不到可归属于旧身份并带裁决的请求。独立的原句柄探针确认隧道恢复时同一进程仍活着，而旧 exec 输入流已关闭。业务双写、自然 worker 四类拒写以及换主是否确实造成业务损害，在相应自然轮次保持未知。
