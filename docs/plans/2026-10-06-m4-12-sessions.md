# M4 Plan 12：会话后端（session / incarnation、turn、工具额度、会话 API 与事件流）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> **执行方式**：有界多 agent：协调者负责接口、集成与验收；每个任务一个隔离 worktree、一个子 agent；**运行验收（root、真实沙箱、PostgreSQL 端口共享）串行**。每个任务 TDD。命令与环境见 `.superpowers/sdd-m4/exec-context.md`。

**Goal:** 实现 [M4 第一部分设计](../superpowers/specs/2026-10-06-m4-chat-sessions-design.md) 第 2、3、5、6、8、9 节中属于 Plan 12 的部分：按 v0.2 规格 §12 的完整会话（每会话一个长期 incarnation，冻结 / 驱逐 / 恢复 / 关闭 / 重启），turn 即 session task，新消息到达时取消并保留已停止的 turn，恢复（Restore）的种子 checkpoint，`awaiting_input`，Gateway 强制的每 turn 30 次工具调用额度，会话 API 与整会话 SSE 事件流，用户隔离；通过 E28–E33。

**Architecture:** 新包 `internal/session`（纯 `Decide` + session actor + Scheduler，经窄接口使用环境、Worker、Gateway 入口与 admission）；`internal/task` 的 actor 对 session task 走"会话授予"路径（先由 session actor 授予 idle 的 incarnation，再在持有 `sessions FOR UPDATE` 的事务中创建 attempt；"停止环境"改为交还 incarnation：释放或销毁）；`internal/runner` 新增 incarnation 驱动（session 模式协议：`task_start`、`task_outcome`、释放核验、`quiesce`、`session_close`），复用 task 模式的事件处理；`internal/gateway/edge` 增加每 incarnation 一个 listener、连接按当前 attempt 绑定、空闲拒绝；Gateway 的工具额度在 Tx1（登记新调用）中与 `budgets` 行同一事务计数；PostgreSQL migration 0006 建 §6 的会话表并给事件加会话序号；`internal/api` 增加会话与 turn 端点、整会话 SSE（`id = session_seq`）与用户视图映射。

**Tech Stack:** Go 1.24 标准库、PostgreSQL 16（pgx，已有）、cgroup v2（`cgroup.freeze`）。不引入新的 Go 模块。E2E 使用 Go 编写的脚本化 session Worker（`tests/e2e/sessionworker`，`CGO_ENABLED=0` 静态构建），不依赖 Plan 13 的 Python Agent。

**规格依据：** 设计文档第 2、3、5、6、8、9 节；v0.2 规格 §5.2–§5.9（协议与 session 扩展）、§6（数据模型）、§7.1（锁顺序）、§8.1（task 状态机与会话授予）、§8.3（environment frozen）、§9.1–§9.6（Gateway 入口、访问检查、预算）、§12（全部）、§14.1–§14.3（恢复与分类）、§15（API、SSE）、§16.3 I9–I10、§16.4 E28–E33、§19（`T_task_accept` 10 s、`T_release` 30 s）。

## Global Constraints

**摘自设计（原文）：**

- D3：研究方式：工具调用式 Agent（模型决定何时搜索、读哪个网页、何时结束）；每轮 30 次工具调用上限由 Gateway 强制，第 31 次 `429 tool_budget_exhausted`；Agent 在每个工具结果中看到剩余额度
- D4：会话保留到用户删除；自动标题；可重命名、删除；空闲 10 分钟冻结，1 小时（或内存压力下按 LRU）驱逐；新消息唤醒
- D5：已停止的研究遇到新消息：自动取消但保留全部内容，卡片显示"已停止 + 恢复"；其来源与已完成的子主题摘要可作为新一轮的上下文；"恢复"在同一会话中开新一轮，从被取消研究的最后 checkpoint 继续，获得新的 30 次额度
- D6：会话实现：完整的规格 §12 会话（每会话一个长期 incarnation，冻结/驱逐/恢复），覆盖 E28–E33
- **工具额度**：Gateway 按 task 计数 `web_search` 与 `web_fetch`（缓存命中、合并也计数），与预算预留在同一事务内（并发与重启下精确）；上限默认 30（`--turn-tool-budget`）；模型调用、`read_skill`、`read_source`、`ask_user`、`todo_write` 不计数。
- **权限**：会话只属于其所有者；用户只见自己的会话；运维在 `#/admin` 可见全部。
- **生命周期参数**：`--session-idle-freeze`（默认 10 min）、`--session-evict-after`（默认 1 h）；冻结前条件、驱逐、唤醒、冷恢复的 state 读取、关闭与 server 重启按规格 §12.2、§12.6。
- **新消息到达时有 paused turn**：该 turn 被取消（裁决事务内清除会话队列阻塞），内容全部保留，卡片显示"已停止 + 恢复"；其来源与已完成的子主题摘要作为新一轮的可用上下文。
- **恢复**：在同一会话新建 turn（`restored_from_task_id`），从被取消 turn 的最后 task checkpoint 继续（该 blob 已授权到本会话 scope），新的 30 次额度。
- **`ask_user`**：turn 进入 `awaiting_input`（一种暂停：保留 checkpoint、释放 run slot）；用户的回答恢复同一 turn 的同一位置；不计入 30 次。
- **删除会话**：拒绝新消息 → 排队与暂停的 turn 取消 → 运行中的 turn 取消并释放 → 环境停止后删除 workspace；已固定的报告保留在运维记录中，从用户视图消失。
- **原始请求/响应（⟨/⟩）**：用户可见工具的输入、输出与发给模型的提示；不可见 Key、费用与内部调用 ID（沿用 Plan 11 的服务端脱敏，运维可见全部）。
- 单个工具调用失败（如网页不可达）：记录并继续，计 1 次额度。
- 唤醒失败：会话转 `evicted` 并按冷恢复重试一次；仍失败则提示"会话暂时无法恢复"，历史仍可阅读。
- 运行验收（root、真实沙箱）串行。

**本计划的约束：**

- **契约唯一**：`api/openapi.yaml`（Task 1）是会话 API 与事件的唯一契约，Plan 13 的前端类型由它生成；协议 v1 session 扩展以 `protocol/v1/session.schema.json` + `protocol/fixtures/v1/session_messages.json`（Task 2）为准。之后的任务**不得修改**这两份契约；发现缺口时报告 NEEDS_CONTEXT，由协调者修订契约并通知 Plan 13。
- **写入所有权**（规格 §6、§3.2）：`sessions` 生命周期列只由 session actor（及启动恢复）写；例外是规格 §8.1 规定的会话 task attempt 创建事务（清除 `blocked_by_task_id`、设置 `current_task_id`、`idle → running`）与裁决事务（设置/清除 `blocked_by_task_id`、`current_task_id`、推进 `session_progress`）。`session_control` 与 `task_control` 只由 API 事务写。
- **锁顺序**（规格 §7.1 增补）：`sessions → session_control → session_progress → tasks → task_control → task_progress → task_event_seq → session_event_seq → subruns → attempts → …（其余不变）`。会话 task 的 attempt 创建、最终裁决、`paused → cancelled` 的控制应用，从 `sessions FOR UPDATE` 开始。
- **会话事件序号**：每条属于会话 task 的事件（host 与 worker）与每条会话生命周期事件，在插入事务内从 `session_event_seq` 行锁分配 `session_seq`（单调、连续、提交顺序即序号顺序）；SSE `id = session_seq`。
- **工具额度**只在 Tx1 **新插入** `calls` 行时计数（同 call_id 的重放、复位后接管的 `resolving` 不再计数；新 call_id 的 supersede 计数）；独立任务 `tool_call_limit IS NULL` 不受限。拒绝不创建调用记录。
- **turn 不排队**：会话中已有 `queued`/`running`/`cancelling` 的 turn 时新消息 `409 turn_in_progress`；有 `paused`（含 `awaiting_input`）或 `pausing` 的 turn 时先对它写 cancel 控制（reason `superseded`），再插入新 turn。
- **每用户同时 1 个运行中**（Plan 11）延伸到会话：用户全部会话与研究中 `queued|running|pausing|cancelling` 的任务至多 1 个（`paused` 不计），否则 `409 user_task_running`。
- **测试**：Go 每包一个 `*_test.go`（追加段落）；需要数据库的用例读 `AGENTBOX_TEST_DATABASE_URL`，`CI=true` 时缺失即失败；需要 root 的用例非 root 时 `t.Skip` 且必须在 root 命令下真实运行一次。不写琐碎测试：每条契约规则或风险路径一个用例。
- **分支**：集成分支 `m4-batch`；每个任务一个 worktree；不推送、不合并（另行授权）。

|---|---|---|

| `POST /turns/{id}/stop` · `/continue` · `/finish` · `/answer` | `{request_id}`；`/answer` 另需 `{answers: [{question_id, choice?, other?}]}`（1–3 项） | `202 {turn_id, control_version}` |

错误码（新增）：`session_not_found`、`turn_not_found`、`session_closed`（409）、`turn_in_progress`（409）、`invalid_turn_state`（409：如对非 paused 的 turn `continue`、对非 `awaiting_input` 的 turn `answer`）、`not_restorable`（409）、`invalid_text`、`invalid_title`、`invalid_answers`（400）、`sessions_unavailable`（503：未配置会话 Worker）；沿用 `user_task_running`、`request_conflict`、`invalid_cursor`、`forbidden`。

**模式：**

- `Session{session_id, title, state, last_active_at, created_at, owner?, internal_state?}`；`state` ∈ `idle|running|frozen|evicted|restoring|closing|closed`（用户视图：`creating`、`quiescing` 显示为 `idle`，`evicting` 显示为 `frozen`）；`owner`、`internal_state` 只在运维视图出现。
- `Turn{turn_id, turn_index, text, deep_research, status, status_reason?, route?, restored_from_turn_id?, restorable, tool_calls_used, tool_call_limit, summary?, report?{artifact_id, version}, user_message?, created_at}`；`status` ∈ `queued|running|stopping|paused|awaiting_input|succeeded|failed|cancelled`。
- `SessionEvent{seq, turn_id?, type, ts, data, internal?}`，`type` 与 `data`（`oneOf` + `discriminator: type`）：

| type | 来源 | data |
|---|---|---|
| `session_state` | 会话生命周期 | `{state, user_message?}`（`frozen`、`evicted`、`restoring`、`idle`、`closed`；恢复失败时 `user_message = "会话暂时无法恢复"`） |
| `turn_created` | host `task_created`（会话 turn） | `{turn_index, text, deep_research, restored_from_turn_id?}` |
| `turn_status` | host `control_applied`、`attempt_ended`、`task_terminal` | `{status, reason?, user_message?}`（`failed` 时 `user_message = "模型服务暂时不可用，请重试"`） |
| `route` | worker progress `kind=route` | `{route: answer\|research, forced: bool}` |
| `skill_read` | progress | `{step_id, name}` |
| `thinking` | progress | `{step_id, text, raw?}` |
| `ask_user` | progress | `{step_id, questions: [{id, question, options: string[], allow_other}]}`（≤ 3） |
| `todo_updated` | progress | `{items: [{id, title, status: pending\|in_progress\|done\|skipped, budget_share?}]}` |
| `tool_call` | progress | `{step_id, tool, input, raw?}`（`tool` ∈ `web_search\|web_fetch\|read_source\|read_skill\|ask_user\|todo_write`） |
| `tool_result` | progress | `{step_id, tool, ok, preview, error?, raw?}`（`web_search.preview = {results: [{title, url, site, snippet}]}`；`web_fetch.preview = {title, url, excerpt}`） |
| `budget` | progress | `{used, limit}`（值取自 Gateway 的 `X-Agentbox-Tool-Budget`） |
| `assistant_delta` | progress | `{message_id, text}`（同 `message_id` 的片段按 seq 拼接即回复全文） |
| `report_ready` | progress | `{artifact_id, version, title, partial, tool_budget_reached}` |
| `turn_stopped` | progress | `{card: {subtopics_done, subtopics_total, sources, tool_calls_used, tool_call_limit}, findings, can_finish}` |
| `turn_result` | worker `result` | `{summary, outputs}` |

`raw = {request?, request_truncated?, response_ref?}`：`request` 是 Worker 内联的原始请求（≤ 32 KiB，超出截断并置 `request_truncated`），`response_ref` 是 Gateway 结果 blob 的 sha256（经 `GET /turns/{id}/raw/{sha}` 读取）。Worker 的 `progress.kind` 取上表 progress 来源的 type 名，`progress.data` 即 data；其他 `kind` 对用户不可见。

**消息（规格 §5.4 session 扩展 + 本计划修订）：**

| 方向 | type | 字段 |
|---|---|---|
| 宿主→Worker | `init` | `mode: session, session_id, incarnation_id, config?, session_resume?{checkpoint_id, state \| staged_state_path, refs[]}`（不带 `state_ref`） |
| 宿主→Worker | `task_start` | `task_id, attempt_id, attempt_no ≥ 1, traceparent?, config, config_version?, budget_limits?, input_refs[], out_dir, base_session_checkpoint_id?（空 = 会话尚无 checkpoint）, resume?, directive?{kind: continue\|finish_now\|answer, answers?[]}` |
| 宿主→Worker | `task_outcome` | `attempt_id, verdict: succeeded\|failed\|cancelled\|paused, committed_session_checkpoint_id?` |
| 宿主→Worker | `quiesce` / `session_close` | `grace_ms ≥ 0` |
| 宿主→Worker | `checkpoint_result`、`artifact_result`、`cancel`、`pause` | 同 task 模式；session 模式下 `checkpoint_result`/`artifact_result` 另需 `attempt_id` |
| Worker→宿主 | `ready` | 另需 `session_ext: 1`（`mode = session` 时） |
| Worker→宿主 | `task_accepted` / `task_outcome_query` / `task_released` | `attempt_id` |
| Worker→宿主 | `quiesced` | `session_checkpoint_id`（会话尚无 checkpoint 时为空串） |
| Worker→宿主 | `closed` | — |
| Worker→宿主 | **`awaiting_input`**（修订） | `attempt_id, checkpoint_id`：终态提议，`checkpoint_id` 须为最新已提交 task checkpoint |
| Worker→宿主 | `progress`、`artifact`、`checkpoint`、`checkpoint_query`、`paused`、`result`、`error` | session 模式下全部另需 `attempt_id`；`result` 可带 `session_state?{checkpoint_id, state \| state_ref, refs[]}` |

**session 模式事件流**（`SessionStream`）：`awaiting_init → ready → idle`；`idle` 收到宿主 `task_start(A)` 后 → `starting(A)`，`task_accepted(A)` → `active(A)`；终态提议（`result`、`error`、`paused`、`awaiting_input`）→ `proposed(A)`，其后只允许 `checkpoint_query`、`task_outcome_query(A)`、`task_released(A)`；`task_released(A)` → `idle`；`idle` 收到 `quiesce` 后只允许 `quiesced` → `quiesced`（之后宿主可再发 `task_start`，回到 `starting`）；`session_close` 之后只允许 `closed`。`seq` 每 incarnation 从 1 严格递增。违规码沿用 `seq_invalid`、`after_terminal`，新增 `wrong_attempt`（事件的 `attempt_id` 不是当前 attempt）、`not_idle`（`idle` 之外出现 `quiesced`）、`session_ext_missing`。
