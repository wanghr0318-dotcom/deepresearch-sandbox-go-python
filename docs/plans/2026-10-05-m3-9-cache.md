# M3 Plan 9：Redis 缓存、请求合并与缓存收益测量

> **执行方式**：有界多 agent（同 M2）：主 agent 负责接口、集成与验收；子 agent 在隔离 worktree 中实现指定文件；运行验收串行（WSL、PostgreSQL、Redis、端口共享）。每个任务 TDD。
> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development。

**Goal:** 实现规格 §11：公开搜索结果与抓取页面的跨任务缓存（journal → 缓存 → 上游）、键与 HMAC 签名值、RFC 9111 子集新鲜度与准入规则、进程内 singleflight 合并、Redis 降级与熔断、密钥轮换；完成 E19（共享请求变体）、E21–E25、I14（缓存部分）、I15，以及缓存收益测量。

**Architecture:** `internal/gateway/cache` 只做缓存键、准入、新鲜度、值编码与签名校验、Redis 适配与熔断，不记账、不授权；`gateway/call` 在 Tx1 与 Tx2 之间插入"查缓存"分支（§11.2），命中走新的事务用例 `CompleteFromCache`（无预留），未命中照常预留与上游；结果写缓存在结算之后异步进行、可丢弃。Redis 客户端为标准库实现的最小 RESP2 客户端（离线 Go 模块代理中没有 Redis 客户端，且只需要 `PING/GET/SET PX/DEL`）。模型调用不缓存。

**Tech Stack:** Go 1.23 标准库（RESP2 over TCP、HMAC-SHA256、`golang.org/x` 不引入）、Redis 7（docker compose）、PostgreSQL 16。

**规格依据：** §11（全部）、§9.4（journal 优先、`source = cache|coalesced`）、§9.1 离开原因表（共享请求只被取消类原因取消）、§16.3 I14（缓存部分）、I15、§16.4 E19（singleflight 变体）、E21–E25、§16.6 缓存收益、§19（Redis 读/写超时 50/100 ms、熔断 5 次/30 s、可缓存响应 ≤ 2 MiB、缓存值 ≤ 4 KiB、搜索 TTL 6 h）。

## Global Constraints

- **正确性不依赖 Redis**：Redis 不保存任务状态、预算、恢复依据或锁；Redis 任何错误 → 视为未命中；PostgreSQL 或访问检查失败 → 返回错误，不绕过（§11.2）。
- **journal 优先**：已记录的调用结果永不被缓存覆盖；同 call id 的重放先于缓存。
- **只有 Gateway 写缓存**；每次命中校验 HMAC、`expires_at`（Gateway 时钟）、blob 存在且内容哈希一致，任一失败 → 未命中、删除条目、记录 `cache_integrity_failure`。
- **依赖方向**（archtest）：`gateway/cache` 不依赖 `persistence`、`gateway/call`、`net/http`；`gateway/call` 只经窄接口使用 `cache`。
- **默认值**（§19）：读 50 ms、写 100 ms 超时；连续 5 次失败熔断 30 s；可缓存响应 ≤ 2 MiB；缓存值 ≤ 4 KiB；搜索 TTL 6 h；`expires_at` 上限 24 h。
- **密钥**：`<data>/cache.key`（0600，安装时生成）；`agentbox cache rotate-key` 轮换；当前与上一 `kid` 可验证。
- **测试**：每包一个 `*_test.go`；Redis 相关用例在 CI 用 Redis service 容器、本地用 compose 的 Redis；数据库用例只在真实 PostgreSQL 上测试。
- **分支**：`m3-batch`，自 `m2-batch` 创建；推送与合并另行授权。

**Files:** Modify `deploy/docker-compose.yml`（`redis:7-alpine`，仅绑定 127.0.0.1:6379）、`.github/workflows/ci.yml`（correctness 与 linux-integration 增加 Redis service）；Create `internal/gateway/cache/redis.go`、`internal/gateway/cache/breaker.go`、`internal/gateway/cache/cache_test.go`。

**Interfaces：**

```go
package cache

type KV interface { // 由 Redis 实现；测试可用内存实现
    Get(ctx context.Context, key string) ([]byte, bool, error)
    Set(ctx context.Context, key string, val []byte, ttl time.Duration) error
    Del(ctx context.Context, key string) error
}
type RedisConfig struct{ Addr string; ReadTimeout, WriteTimeout time.Duration /* 50ms / 100ms */; PoolSize int /* 8 */ }
func NewRedis(cfg RedisConfig) *Redis // 标准库 RESP2：PING、GET、SET key val PX ms、DEL；连接池；每次操作独立期限
type Breaker struct{ /* 连续失败 5 次 → 打开 30 s → 半开试探 */ }
type Metrics struct{ Hit, Miss, Bypass, Coalesced, Error, BreakerOpen, IntegrityFailure atomic.Int64 }
func Guarded(kv KV, b *Breaker, m *Metrics) KV // 熔断打开或出错 → 视为未命中（Get 返回 false, nil），写入失败只计数
```

**Tests：** 对真实 Redis（`AGENTBOX_TEST_REDIS_ADDR`，CI 与 compose 提供；`CI=true` 时缺失为失败）：GET/SET/PX/DEL 往返；读超时（对一个不回复的 TCP 服务）50 ms 内返回并计为错误；连续 5 次错误后熔断打开、30 s 后半开（注入时钟）；RESP 协议解析的边界（空值、错误回复、大值拒绝 > 4 KiB）。

**验证：** `docker compose -f deploy/docker-compose.yml up -d --wait`；`CI=true AGENTBOX_TEST_REDIS_ADDR=127.0.0.1:6379 go test -count=1 ./internal/gateway/cache/`。

### Task 2：键、准入、新鲜度、值与签名、密钥

**Files:** Create `internal/gateway/cache/key.go`、`admit.go`、`freshness.go`、`value.go`、`keyfile.go`（与 Task 1 共用 `cache_test.go`，各自追加独立的测试函数）；Modify `cmd/agentbox/main.go` + `init_linux.go`（`agentbox cache rotate-key --data-dir`）。

**Interfaces：**

```go
func Key(kind upstream.Kind, provider, adapterVersion string, params []byte) (string, error) // v1:{search|fetch}:{provider}:{ver}:sha256(JCS(规范化参数))
func NormalizeURL(raw string) (string, error) // scheme/host 小写、去默认端口、去 fragment，查询串原样
type Response struct{ Status int; Header http.Header /* 只读 */; Size int64; Date, RequestTime, ResponseTime time.Time }
func Admit(kind upstream.Kind, rawURL string, r Response) (ok bool, reason string) // §11.3 准入：仅 GET、200、≤ 2 MiB、无 Set-Cookie / no-store|private|no-cache / Vary:* 或除 Accept-Encoding 外的维度、URL 不含凭据类参数
func Lifetime(r Response, now time.Time) (expiresAt time.Time, ok bool) // s-maxage > max-age > Expires−Date；无显式新鲜度不缓存；完整年龄计算；上限 24 h；不延长
type Value struct{ BlobSHA256 string; Status int; ContentType, FinalURL string; Size int64; FetchedAt, ExpiresAt time.Time; KID string; MAC []byte }
type Signer struct{ /* 当前与上一密钥 */ }
func LoadKeys(dataDir string) (*Signer, error)           // <data>/cache.key 0600；不存在时生成
func RotateKey(dataDir string) error                       // 当前 → 上一，生成新当前
func (s *Signer) Seal(key string, v Value) ([]byte, error) // JSON + HMAC（覆盖键、元数据、expires_at、kid），≤ 4 KiB
func (s *Signer) Open(key string, raw []byte, now time.Time) (Value, error) // 验 MAC、kid ∈ {当前, 上一}、未过期；限长解析
```

**Tests：** 键对参数顺序不敏感、对 provider/版本敏感；URL 规范化表；准入表（逐条 §11.3 拒绝原因）；新鲜度表（E25：短 max-age、Age、Vary、Expires−Date、冲突头、无显式新鲜度、24 h 上限、不延长）；签名往返、篡改 MAC/键/expires_at/kid 均失败；轮换后上一 kid 仍可验证、再轮换后失效；超过 4 KiB 拒绝。

**验证：** `go test -count=1 ./internal/gateway/cache/`。

### Task 3：`gateway/call` 的缓存分支与 `CompleteFromCache`

**Files:** Modify `internal/gateway/call/{call.go,store.go,call_test.go}`、`internal/persistence/postgres/{gateway.go,postgres_test.go}`、`internal/app/{app.go,adapters.go}`、`cmd/agentbox/server.go`（`--redis-addr`、`--cache=on|off`）。

**Interfaces：**

```go
// call.Store 新增：
CompleteFromCache(ctx context.Context, r CacheCompletion) (CallRecord, error) // Tx2：复查访问（含 desired ≠ cancel）→ scope_blobs(task) → calls.completed(source=cache, result_ref)；无预留、无 try
type CacheCompletion struct{ TaskID, CallID, AttemptID, ResultSHA256 string; ResultSize int64 }
// call.Config 新增 Cache CacheSource（nil = 关闭）：
type CacheSource interface {
    Lookup(ctx context.Context, kind upstream.Kind, provider, ver string, params []byte, rawURL string) (blobSHA string, size int64, hit bool)
    Store(kind upstream.Kind, provider, ver string, params []byte, rawURL string, resp cache.Response, blobSHA string) // 异步、可丢弃
}
```

**规则（§11.2）：** Tx1 `BeginCall` → 查缓存（事务外；只对 search/fetch；`no-cache` 请求头 `X-Agentbox-Cache: no-cache` 时跳过读取但仍写入，且计入指纹）→ 命中：校验 blob 存在且哈希一致（`BlobStore.Open` 复算）→ `CompleteFromCache`；取消先提交则 Tx2 拒绝、结果不授权（E23）→ 未命中：照常 `ReserveTry` → 上游 → 结算后异步 `Store`（准入与新鲜度由 cache 判定）。命中计入抓取请求次数与字节配额（M2 的抓取配额计数沿用 `usage`）。Redis 失败 → 未命中；PostgreSQL 失败 → 错误。每次命中重新检查当前策略（URL 校验器、provider 启用）。

**Tests：** 命中不预留、不计上游；journal 重放先于缓存；no-cache 不读但写；完整性失败（blob 缺失/哈希不符）→ 未命中且删除条目；取消先提交 → 命中不授权（E23，真实 PostgreSQL）；Redis 停止 → 全部 miss、任务结果正确。

**验证：** `CI=true … go test -count=1 ./internal/gateway/... ./internal/persistence/postgres/ ./internal/app/`。

### Task 4：singleflight 合并

**Files:** Modify `internal/gateway/call/{call.go,call_test.go}`。

**规则（§11.4）：** 合并键 `(task_id, attempt_id, subrun_id|"root", cache_key)`；不跨 sub-run、attempt、任务；共享请求用 Gateway 自有 context 与期限；waiter 离开不终止它；只有取消类原因（任务取消、该 sub-run 取消）取消它；leader 付费；follower 各自访问复查、配额计数、journal 提交 `source = coalesced`（无上游费用）；`no-cache` 不加入任何 singleflight。

**Tests：** 同 attempt 10 个相同抓取 → 1 次上游、9 个 `coalesced`；两个 sub-run（以 `X-Agentbox-Subrun` 区分；M3 中 sub-run 头仅用于合并键测试，不改变记账）同一抓取 → 不合并；leader 的 Worker 断开 → 共享请求继续，follower 拿到结果；任务取消 → 共享请求取消，各方结算；E19 共享请求变体（attempt 替换时共享请求继续至期限并入 journal）。

**验证：** `go test -count=20 ./internal/gateway/call/`。

### Task 5：不变量、故障实验与缓存收益

**Files:** Modify `internal/invariants/invariants.go`、`internal/persistence/postgres/invariants.go`、`tests/e2e/e2e_test.go`（追加）、`tests/e2e/fakeupstream/*`（可配置缓存头）；Create `bench/cache/run.sh`、`docs/evidence/2026-10-XX-m3-cache-benefit.md`（运行后填写）。

**规则与用例：**
- **I14（缓存部分）**：每个 `source = cache|coalesced` 的调用都有 `scope_blobs(task)` 记录且结果不变；**I15**：恢复完成后不存在没有活跃 attempt 的 `resolving` 调用。
- **E21**：Redis 宕机（停止容器）、变慢（TCP 代理注入延迟 > 50 ms）、熔断 → 任务结果正确；`/status`（或 `inspect`）可见 miss/bypass/breaker_open 计数。
- **E22**：错误 HMAC、替换 blob sha、过 `expires_at` 后重放签名条目、超大值 → 均为未命中并记录 `cache_integrity_failure`。
- **E23**：缓存命中与取消竞争 → 取消先提交则结果不被授权。
- **E24**：同一 sub-run 内 10 个相同抓取 → 一次上游；两个 sub-run 同一抓取 → 不合并。
- **E25**：新鲜度表在 e2e 中以 fake upstream 的响应头复现（寿命不延长、不支持的情况不缓存）。
- **缓存收益**（§16.6）：用**新的逻辑任务与 call ID** 重复相同查询（避免测到 journal 重放）：记录命中率、命中与上游延迟分布、上游调用减少量；10 次 × 2 组（缓存开/关），原始数据与环境写入证据文件。

**验证：** `CI=true … go test -count=1 ./tests/e2e/...`（含 root 真实沙箱用例，连续三次）；`bash bench/cache/run.sh`。
