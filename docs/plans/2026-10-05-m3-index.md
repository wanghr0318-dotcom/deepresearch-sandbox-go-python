## 门槛判定（2026-10-06）

- **已集成并验证**：Redis 缓存（RESP2 客户端、熔断、键与准入、RFC 9111 子集新鲜度、HMAC 签名与轮换、`CompleteFromCache`、singleflight 合并）；结果/产物下载端点；浏览器安全（Origin/Host 允许列表、CSP 等安全头、可选 TLS、同源静态提供）；Vue 工作台（生成类型、SSE 客户端、视图）；E16（Vue）、E19（共享请求）、E21–E27、I14（缓存部分）、I15 由 CI 与 root e2e 覆盖。
- **服务器真实验收**（原生 Linux）：root 全量连续三次 1268 通过；serper + Redis + 工作台真实研究演示 15 步通过；HTTPS 常驻服务公网可达且未授权请求被拒。记录：[M3 服务器验收](../evidence/2026-10-06-m3-server-acceptance.md)。
- **仅验证可行性**：缓存收益的数字来自 WSL2 + fake upstream（[缓存收益](../evidence/2026-10-05-m3-cache-benefit.md)），真实网络下的命中率未测；sub-run 维度的合并键只在 call 层测试（sub-run 在 M4）。
- **CI**：`m3-batch` @ c04dcb1，run 37346784990 全部作业通过（correctness、linux-integration（root，任何非允许跳过即失败）、web、python 3.11/3.13、complexity-report）。
- **判定：M3 门槛通过**。项目负责人在浏览器中的试用随 Plan 11 一并进行。

## 待审批的决定

1. Redis 客户端自研最小 RESP2（离线 Go 模块代理没有 Redis 客户端；只需 `PING/GET/SET PX/DEL`），不引入第三方 Go 模块。
2. 缓存默认开启；未配置 `--redis-addr` 时等价于关闭。
3. 工作台放在 `web/`，由 `agentbox server --web-dir` 同源提供（不开 CORS）；token 默认只存内存。
4. 前端依赖：保留 `vue`、`vite`、`marked`、`typescript`，新增 `dompurify`、`openapi-typescript`、`vitest`、`@vue/test-utils`；Playwright 可选。
5. 下载端点（`GET /tasks/{id}/result`、`/artifacts/{artifact_id}`）在 M3 实现，解除 M1/M2 的 501 限制。
6. sub-run 泳道与会话视图只预留，真实数据在 M4。
