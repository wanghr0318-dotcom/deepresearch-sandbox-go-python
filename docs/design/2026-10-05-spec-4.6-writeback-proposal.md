## 1. 相对候选序列的修改（实验证明候选写法不成立的两处）

1. **附加组在宿主侧、clone 之前清空。** 写入 `setgroups=deny` 之后，命名空间内任何进程都不能再调用 `setgroups`；Go 的 `SysProcAttr.Credential{Groups: []}` 在 GID 映射且 setgroups 被拒的配置下**静默跳过** setgroups，宿主的组 0 以 65534 留在 workload 中。对照实验：不清空或经 `Credential` 清空均失败，宿主侧 `setgroups([])` 成功。
2. **securebits 在 helper 中、`setresuid` 之前设置并锁定（0x0f），且不在 init 中设置。** 候选顺序（先切换 UID 再设 securebits）实测 `EPERM`：切换后 `CAP_SETPCAP` 已不可用。在 init 中设置则 helper 经 `execveat` 拿不到能力。

## 2. 提议的 §4.6 正文（取代候选代码块）

```
宿主（root）：分配 UID/GID 范围与 cgroup；在 clone 之前清空附加组并断言 Groups 为空
→ clone（CLONE_INTO_CGROUP）：NEWUSER|NEWNS|NEWPID|NEWUTS|NEWIPC|NEWNET；
   父进程依次写 setgroups=deny → gid_map → uid_map；子进程在 ns 内 setgid(0)/setuid(0)（不调用 setgroups）后 execve init
→ init（ns uid 0）：
   控制 socket 立即以 F_DUPFD_CLOEXEC 移到高位并关闭原 fd（ExtraFiles 继承时不带 FD_CLOEXEC）
   mount("/", MS_REC|MS_PRIVATE)
   rootfs：新挂载 API——open_tree(OPEN_TREE_CLONE|AT_RECURSIVE) → mount_setattr(AT_RECURSIVE, RDONLY|NOSUID|NODEV,
     MS_PRIVATE)（树游离时设置）→ move_mount；/in 同法。回退：mount(2) MS_BIND|MS_REC 后逐个子挂载 remount ro。
     不采用"clone 前宿主侧挂载"：宿主可见，且 pivot_root 视其为锁定挂载
   tmpfs：/tmp、/run（限额）；exec 环境 /out；/dev = tmpfs + bind null/zero/random/urandom 后 remount ro
   编排环境 bind Gateway socket（属主为映射 uid 1000，0600）；session bind workspace
   新 proc 实例（nosuid,nodev,noexec）→ §4.5 掩蔽清单（目录：只读空 tmpfs；文件：bind /dev/null）→ 只读路径
   打开 helper 二进制 O_PATH|O_CLOEXEC 并移到高位（pivot_root 之前）
   pivot_root(".", ".") → umount2(".", MNT_DETACH) → chdir("/")
   全部线程：bounding = {KILL, SETUID, SETGID, SETPCAP}；permitted = effective = {KILL}；inheritable = 0；不设 securebits
→ 每个 workload（持 reg.mu）：
   recvmsg(MSG_CMSG_CLOEXEC) 恰好 3 个 FD；exec-status 管道 pipe2(O_CLOEXEC)；源 FD 全部移到高位
   阻塞全部信号 → clone(SIGCHLD) → 子进程：dup3 到 0/1/2 与 3（exec-status），setpgid(0,0)，清空信号掩码，
     execveat(helper_fd, "", AT_EMPTY_PATH)
   stage-2 helper（CGO_ENABLED=0；LockOSThread；身份与能力调用经 AllThreadsSyscall 作用于全部线程）：
     PR_SET_NAME → fd 3 设 FD_CLOEXEC，close_range(4, ~0, CLOSE_RANGE_CLOEXEC)
     → 清空 bounding → 设置并锁定 securebits（NOROOT|NO_SETUID_FIXUP 及其 LOCKED 位）
     → setresgid/setresuid(1000) → 显式清空 eff/prm/inh 与 ambient → 显式设置 RLIMIT_NOFILE 等（§4.5）
     → no_new_privs → seccomp(SECCOMP_FILTER_FLAG_TSYNC，clone3 → ENOSYS) → execve workload
   init：exec-status 管道有数据 → start_err{reason}；EOF 后确认 helper 已完成 exec 才 start_ack，否则 start_err
→ 任何步骤失败：init 阶段 → 环境创建失败；workload 阶段 → start_err，workload 不运行
```

失败行为表（每个注入点 → `init_err`/`start_err` 原因文本）见实验记录 §8：init 9 个注入点、每次启动 12 个注入点，workload 均未运行。

## 3. §16.2 的修订

- "`Seccomp: 2` 且 `Seccomp_filters ≥ 1`"改为"`Seccomp: 2` 且 `Seccomp_filters ≥ 宿主基线 + 1`"：WSL2 的 init 给每个进程预装 1 个 filter，原写法无判别力。

## 4. 开放风险与处理

| 编号 | 风险 | 提议的处理 |
|---|---|---|
| R1 | 只验证了 WSL2 6.6 一个内核 | 发布门槛前在裸机 Linux（systemd 下 `/` 为 shared 传播、AppArmor 用户命名空间限制、新挂载 API 与 `close_range` 支持、aarch64 seccomp）复跑 `run.sh`；`hostcheck` 检查新挂载 API 与 `close_range` 可用 |
| R2 | 标准库无 `execveat`：init 用 raw clone + nosplit 函数，依赖 Go 运行时内部行为 | 生产实现单独评审，函数最小化并有回归测试 |
| R3 | "helper 在 exec 前死亡"依赖 comm 变化与短轮询；workload 恰好名为 `agentbox-helper` 时误判 | 生产实现改用不依赖 comm 的判据（需在 Plan 2 Task 9 设计中给出并测试），本提案不固定具体方法 |
| R4 | workload 继承 Go 运行时调高的 `RLIMIT_NOFILE`（软限 10240 → 1048575） | helper 显式设置 rlimit（已写入第 2 节） |
| R5 | session 恢复只以"两个实例共用 UID 范围"模拟，未覆盖 agentbox 重启 | 属于 M4 的 E28 验收 |
| R6 | 新挂载 API 只用于 bind；proc 与 tmpfs 仍用 mount(2) | 接受（功能等价，已验证） |
| R7 | 模板不提供 `/dev/shm`，Python `multiprocessing` 不可用 | **需决定**：是否在编排环境加入限额 tmpfs `/dev/shm`（规格 §4.5 未列出；加入即修改 §4.5） |
| R8 | helper 依赖 `CGO_ENABLED=0`（cgo 下 `AllThreadsSyscall` 返回 ENOTSUP） | 构建与 CI 固定 `CGO_ENABLED=0` 构建 helper；archtest 或构建脚本检查 |
