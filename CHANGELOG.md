# Changelog

## v0.4.0 — 2026-10-12

Multi-tenant model gateway release: orgs and platform API keys, rate limits and monthly budgets, an OpenAI and Anthropic model API with conversion in both directions, usage, bills and reconciliation, and the load-test, fault-injection and demo evidence for them.

- **Model gateway evidence (G6):** `cmd/agentbox-loadtest` (scenarios `latency`, `ladder`, `ratelimit`, `budget`, `steady`, `lockwait`; `--rpm` / `--tpm` put the rate limiter on the path for `latency` and `ladder`; seeded, JSON-lines results, database password redacted) with `scripts/loadtest-gateway.sh`, which runs it against a local server, `fakeupstream` providers and a disposable Redis; `scripts/fault-gateway.sh` (server killed mid-stream → `charged_unknown` by the sweep, provider failure after the first byte, key revoked mid-stream, breaker open and recovery); `scripts/demo-gateway.sh` (orgs, invite, keys, both official SDKs on all four paths with streaming and tool calls, weighted routing, 429 rate limit and `insufficient_quota`, revocation, metrics), sharing `scripts/lib/gateway.sh`; Grafana dashboard "Agentbox model gateway" (provisioned with the observability stack; not yet checked against a live Grafana); `fakeupstream -tool-calls`; fakeupstream records the usage it reports and prints a `usage` line on exit, which the load test uses to cross-check requests, holds and tokens independently. The scripts start PostgreSQL from `deploy/docker-compose.yml` when no `AGENTBOX_DATABASE_URL` is given and only ever clear a work directory they created. Results in `docs/evidence/2026-10-12-model-gateway.md`.
- **Fix: Redis connection pool after a Redis restart.** An I/O error that means the server closed the connection (EOF, reset, broken pipe) now drops every idle pooled connection. Before, each operation took one dead pooled connection and failed again, so the rate limiter (which retries Redis once per 5 s cool-off) stayed degraded for up to "idle connections × 5 s" after Redis came back (seen in the load test).
- **Model API: SDK `model_dump()` history accepted.** A previous response sent back as a plain `model_dump()` (anthropic 1.x adds `caller: null`, `toolset_name: null` and `citations: null` to content blocks; openai adds `parsed: null` and null `refusal`/`annotations`/`audio`/`function_call`/`tool_calls` to messages) no longer gets `400 unsupported_field`. Null or empty unknown fields on messages and content blocks are ignored; unknown fields with a value are still refused, and pass-through still forwards the original body.
- **Usage, bills and reconciliation (model gateway G5):** migration 0015 adds `usage_daily` (per UTC day, org, user, key, model and source `runtime` | `model_api`: requests, prompt/completion tokens, `cost_micro`, `unknown_micro`) and `usage_rollup_state`. New `internal/usage`; with accounts on, the server rolls settled and charged_unknown budget holds into `usage_daily` every minute (model and tokens from `model_requests`, or the sandbox call's model / endpoint for runtime calls), incrementally from a watermark (the oldest day with a held hold, at most the day of one hour ago), idempotently, serialised across servers by an advisory lock in one REPEATABLE READ snapshot. `GET /v1/usage?from&to&group_by=day,model,key,user,org,source` and `GET /v1/bills/{yyyy-mm}` (members their own, owners their org, the operator all with `?org=`; API keys 403) and `GET /v1/orgs/members` (owners). CLI `agentbox usage`, `agentbox bill show <yyyy-mm>` and `agentbox bill reconcile <yyyy-mm>` (recomputes the month from the raw holds and model requests, compares with `usage_daily` and `quota_budgets` per org/user/key/model, exits 1 on differences); `verify-invariants --usage-month YYYY-MM` adds the same comparison as `U1`. Web: API keys page (create with scopes and expiry, the full key shown once with copy, revoke with confirmation), usage page (daily cost and token SVG bar charts, by model and by key, budget bars for org/user/key, this month's bill) and members page (members and roles, invites, received invites accept/decline, leave).
- **Model API (model gateway G3):** `agentbox server --model-api` (off by default; needs `--model-base-url`) serves `POST /v1/chat/completions` (OpenAI), `POST /v1/messages` (Anthropic, `anthropic-version` echoed) and `GET /v1/models` to callers with the `models` scope (platform key as `Authorization: Bearer` or `x-api-key`, session cookie, operator token); errors use the caller's format. New package `internal/modelapi` follows design §7.7: decode in the client's format; take `rpm` and estimated `tpm` at the key, user and org level plus a `max_streams` slot (429 `rate_limit_exceeded` with `Retry-After` and `x-ratelimit-*-requests` / `-tokens`; the operator is not limited); resolve candidate routes, keeping requests with format-only features on providers of their format (400 `unsupported_field` when none serves the model); reserve the worst-case cost as a quota hold (429 `insufficient_quota` naming the level; 503 when PostgreSQL is unavailable — no model call without a hold); try routes in the routing plan's order with failover before the first byte (including an `overloaded_error` event before content); forward same-format streams event by event and convert the others; settle with the actual cost, or as `charged_unknown` with the estimate when usage never arrived (client disconnect, provider failure mid-stream, a stream cut after `finish_reason` before its usage). `--model-api-max-duration` (default 10 min) bounds a request; a failure after the first byte ends the stream with an error event in the client's format. Migration 0014 adds `model_requests` and `model_request_tries`, partitioned by month on `created_at` (partitions are created on demand), written after settlement with the conversion's dropped fields; `verify-invariants` adds G3 (every row has exactly one hold, no longer held). Metrics `agentbox_model_requests_total`, `agentbox_model_request_duration_seconds`, `agentbox_model_ttft_seconds`, `agentbox_model_streams_total{complete}`, `agentbox_model_rejections_total{reason}`, `agentbox_model_dropped_fields_total`. Compatibility tests with the official `openai` and `anthropic` Python SDKs against fakeupstream in OpenAI and Anthropic mode (`tests/sdk`, `scripts/sdk-compat.sh`, CI job `sdk-compat`). `n` other than 1 and `logprobs` on non-stream requests are refused. Without `--model-api` nothing changes. Review round 1:
  - a write deadline enforces `--model-api-max-duration` on clients that stop reading;
  - client disconnects and provider 404s (model not found) no longer count against the shared breaker, and a 404 fails over to the next route;
  - new optional `routing.primary_models` in `--model-fallback-file` restricts the primary to listed logical models (old files and fingerprints unchanged; a declared model no route serves exits 2);
  - the input estimate is bytes ÷ 2 + 1024, and only the effective of `max_tokens` / `max_completion_tokens` is forwarded;
  - rpm is taken before the body is read, the body has a 30 s read deadline, and `--model-api-max-body` (8 MiB) bounds its size;
  - month partitions are created single-flight;
  - recording is retried;
  - metrics `agentbox_model_hold_overshoot_total` and `agentbox_model_request_record_failures_total` are added;
  - a wrong method is a 405 in the caller's format;
  - a stream's `max_streams` slot is released before its hold is settled and the request recorded, so a caller's next stream no longer gets a spurious `429` while the previous one's accounting runs (#51).
- **Model gateway, part B2 (provider protocols and routing):** fallback providers can speak the Anthropic Messages API (`"protocol": "anthropic"` in `--model-fallback-file`: `x-api-key` and `anthropic-version` to `/v1/messages`). Sandbox workers keep sending OpenAI-format calls; for an Anthropic provider the Gateway converts the request with `internal/llmproto` and converts the reply back, so workers see the same shape, with journal, replay, fingerprints, reservations and settlement unchanged. Requests with fields only OpenAI has skip Anthropic providers (`unsupported_protocol`). Optional `weight` per provider and `routing.mode`: `ordered` (default without weights, today's behaviour), `weighted` (smooth weighted round-robin over providers whose breaker is ready — closed, or open with its window elapsed so it gets a half-open probe and its share back — the rest by weight as fallback) and `latency` (weight ÷ EWMA latency with a 5% floor; whole-response time for sandbox calls and time to first token for model-API streams, with a penalty sample on timeouts and unknown outcomes); `routing.primary_weight` weights the primary. Prices gain `cache_read` and `cache_write`. `gateway/upstream` adds streaming `DoStream` for both protocols: it returns at the first content (time to first token), so failures before it — including an `overloaded_error` event — are classified like non-stream calls and can fail over; streams have no total size cap; the events buffered before the first content are capped (1024 events or 1 MiB, retryable `upstream_bad_response` beyond that) and `Next` after `Close` fails at once. Tool-call ids that Anthropic rejects (e.g. `functions.web_search:0`) are rewritten consistently on the way to Anthropic providers and `call.ModelRouting` gives the coming model API a routing plan with a protocol filter, breakers and the per-try timeout up to the first event. Old fallback files are valid and behave exactly as before; invalid new fields exit 2. Design: `docs/design/2026-10-11-model-gateway-design.md` §7.6.
- **Model gateway, part B1 (library only, nothing is served yet):** new package `internal/llmproto` (standard library only) with a neutral chat format and OpenAI and Anthropic codecs: requests, non-stream responses and SSE streams in both directions, including tool calls (several per turn, arguments split across chunks), consecutive OpenAI tool messages ⇄ one Anthropic user turn of `tool_result` blocks, stop-reason mapping, and usage with cache read/write tokens. Fields only one format has are dropped and reported (`cache_control`, `metadata.user_id`, sampling hints) or refused with a typed error naming the field (thinking / `reasoning_content`, `reasoning_effort`, images, `n > 1`, `logprobs`, `response_format`); `Request.FormatOnly` tells the router which requests must stay on providers of their own format. Error objects of both formats for the gateway's error classes; a bad provider response is an upstream error (502), and truncated tool arguments in a response are sent to Anthropic clients as `{}` and listed in `Response.Repaired`. Tool ids are mapped to Anthropic's id pattern; `max_completion_tokens` and the assistant fields the openai SDK echoes back are accepted; `max_tokens` is capped at 1,048,576. Fixtures for all four client → provider paths plus round-trip property tests. `fakeupstream` gains an Anthropic mode (`/v1/messages`, non-stream and the Anthropic event stream, `x-api-key` and `anthropic-version` checked), SSE streaming in OpenAI mode (`stream_options.include_usage` honoured) and stream faults (`-fail-after kind:N:K[:error|:midline]`, `-chunk-delay`, `-cache-usage`, `-anthropic-key-env`); its existing behaviour is unchanged. Design: `docs/design/2026-10-11-model-gateway-design.md` §7.
- **Limits and monthly budgets (model gateway G2):** requests-per-minute limits and monthly money budgets at the org, user (scoped to the user's org) and key level (migration 0013: `quota_budgets`, `quota_holds`; limits use the `limits` table from 0012). New `internal/ratelimit`: token buckets taken all-or-nothing over every level by one Redis Lua script (the stdlib RESP client gains `EVAL`/`EVALSHA`), with an in-process fallback when Redis errors or takes over 50 ms (gauge `agentbox_ratelimit_degraded`), and in-process concurrency counters for model streams. New `internal/quota`: holds reserved at every level of a principal in one transaction (lock order org → user → key), settled, released, or swept to `charged_unknown` at their full amount after their deadline; budget rows are created lazily per UTC month and carry the last limit forward (null = unlimited). Every model, search, fetch and MCP call a sandbox makes now also places a hold for its task's org, user and key in the same transaction as its task reservation (both must succeed; `402 insufficient_quota` names the level) and the hold follows the call's settlement and the restart ledger conversion; per-task budgets are unchanged, and without budgets only the hold rows are added. With accounts enabled: `GET/PUT /v1/limits/{kind}/{id}` and `GET/PUT /v1/budgets/{kind}/{id}` (owners for their org's users and keys, never above the org's own limit; the operator for orgs; API keys never), `rpm` enforced on every runtime route that creates a turn or starts a sandbox (`POST /sessions`, `/research`, `/sessions/{id}/messages`, `/sessions/{id}/wake`, `/turns/{id}/restore`, `/continue`, `/finish`, `/answer`) for key and cookie callers (`429 rate_limit_exceeded` with `Retry-After` and `x-ratelimit-*-requests` headers), the org's `max_sandboxes` (org level only) checked at admission with a per-org FIFO queue woken on release (waiting tasks stay `queued`; gauge `agentbox_org_sandbox_waiting`), held reservations whose settlement failed converted to `charged_unknown` every minute through the restart-conversion path, and a hold sweep every 30 s. CLI `agentbox limits set|show`, `agentbox budget set|show`. `verify-invariants` adds G1 (budget rows equal their holds) and G2 (no level above its limit; overshoot from holds settled above their estimate is reported separately).
- **Tenancy and platform API keys (model gateway G1):** orgs, members (owner / member) and API keys `abx_live_<id>_<secret>` (migration 0012). Every user belongs to one org — a personal org `user-<id>` at sign-up, backfilled for existing users, that takes no other members; users join another org only by accepting an owner's invite (`/v1/orgs/invites`, 7 days), can leave by themselves, and the operator can move users directly; operator-created tasks and sessions belong to the reserved org `operator`; tasks and sessions record their org and, when created with a key, the key. Keys are stored only as `HMAC-SHA256(pepper, secret)` with the pepper in `<data>/apikey.pepper` (0600, created atomically on first start; its fingerprint is recorded in the database and a missing or different file refuses to start with exit code 2; every server sharing a database needs the same file), have scopes `runtime` / `models`, optional expiry and revocation, and are accepted as `Authorization: Bearer abx_live_…` or `x-api-key` (a non-`abx_` Bearer is still the operator token, a non-`abx_` `x-api-key` is ignored, and with accounts on an operator token starting with `abx_` refuses to start). A `runtime` key calls the user-facing runtime API (sessions, research, own tasks) as its user; no key can ever mint keys or manage members or orgs (`403 permission_denied`); a bad key is `401 invalid_api_key`. Verified keys are cached for 30 s and evicted at once on every server through PostgreSQL `NOTIFY apikey_changed` (revocation, member moves, disabled users); `last_used_at` is written at most once a minute. New endpoints `GET /v1/me`, `POST/GET/DELETE /v1/keys`, `POST/GET /v1/orgs/invites`, `POST /v1/orgs/invites/{id}/accept`, `DELETE /v1/orgs/invites/{id}`, `DELETE /v1/orgs/members/{user}`, `POST /v1/orgs` and `POST /v1/orgs/members` (operator; an org and its owner are created in one transaction) and CLI `agentbox org create|list|add-member`, `agentbox key create|list|revoke`. `verify-invariants` adds G4 (a live key's org is its user's org) and G5 (rows created with a key belong to its org). The `limits` table is created for the rate limiter (G2). Without accounts nothing changes.
- **Go 1.26 floor:** the module now targets Go 1.26 (`go 1.26.0`, toolchain still go1.27.2) so golang.org/x/net can move to v0.61.0, which fixes the 5 HTTP/2 advisories left in v0.3.0 (x/sys, x/text, x/sync and x/term moved with it). govulncheck now reports no reachable vulnerabilities in dependencies. Building from source needs Go 1.26 or newer; GODEBUG defaults follow Go 1.26 (set `GODEBUG` to restore an old default).

## v0.3.0 — 2026-10-11

Agent-infrastructure release: observability, evaluation platform, Kubernetes provider, model fallback, workspace tools and MCP, trace doctor.

- **Trace doctor (`agentbox doctor-traces`, operator tool):** reads an eval run directory or a time window of a running server (operator API), finds failed and slow tasks and attributes them to root causes with deterministic rules — hung model tries without a per-try timeout, open breakers / degraded mode, provider errors, search/fetch calls cut by the call deadline, refused fetches, tool and cost budget exhaustion, exec timeouts, retry backoff, hedge waste, slow sandbox start, admission queueing, slow stops — each with evidence (server task and call ids, per-provider try counts and latency percentiles, latency shares; trace ids and per-span time from Tempo, metric cross-checks from Prometheus and WARN/ERROR log counts from Loki when the observability stack runs). Proposes changes to an allowlist of server flags with bounds as `proposal.patch`; `--apply-to` writes a new `experiment.flags` (never the input). Optional model step (off by default, hard budget) summarises the findings; its proposals pass the same allowlist. `scripts/demo-doctor.sh` runs the closed loop (mis-configured server → doctor → re-run → `eval compare` with Wilson intervals) at zero model cost. `fakeupstream -every kind:K:action` injects periodic faults. Design: `docs/design/2026-10-10-trace-doctor-design.md`; measured run: `docs/evidence/2026-10-10-trace-doctor.md`.
- **Eval harness:** the checker's fixture hook now also replaces `_io.open`; the docs no longer say unhooked reads "fail closed": reads that bypass the hook (`os.open`, `io.FileIO`, `mmap`, C extensions, subprocesses) see files a solution planted, and such checks also fail for correct solutions, so validate every suite with `--agent reference` first.
- **Model provider fallback:** a logical model can be served by an ordered chain of OpenAI-compatible providers (`--model-fallback-file`). Retryable failures (connect error, 429, 5xx, per-try timeout `--model-try-timeout`, empty response) fail over to the next provider immediately; every provider attempt is a journaled try with its own reservation at that provider's price; replay and fingerprints are unchanged. Per-provider circuit breakers (`--model-breaker-failures`, `--model-breaker-open`) skip a dead provider without spending a try; when every provider is open the Gateway answers `503 model_degraded` at once. Optional hedged requests (`--model-hedge-delay`, off by default; a cancelled sent leg is charged its estimate as unknown). `inspect` shows the provider, skipped providers and hedge flag of each try. Without a fallback file behaviour is unchanged. Design: `docs/design/2026-10-10-model-fallback-design.md`; measurements: `docs/evidence/2026-10-10-model-fallback.md`.
- **Observability (off by default):** OpenTelemetry tracing (`--otlp-endpoint`, `--trace-sample-ratio`) with one trace per user action from the API request through the task actor, attempts, worker start/handshake/checkpoints and into the sandbox — the worker forwards the W3C `traceparent` it receives in `init` / `task_start` to every Gateway call, which the Gateway accepts only within the attempt's own trace; Prometheus `/metrics` on a separate operator-only listener (`--metrics-listen`): task/turn verdicts, attempt ready, submit→ready and stop latency, upstream try latency and errors by provider/model/status, Gateway call results, cost in micro-USD, tool calls per task, sandbox environments, cleanup backlog, run/exec slots; JSON logs carry `trace_id`/`span_id` and can also be written to a file (`--log-file`). `deploy/observability` (OTel Collector, Tempo, Prometheus, Loki + Alloy, Grafana with a provisioned dashboard) and `scripts/demo-observability.sh`.

- **Workspace tools (optional, `--workspace-tools`):** a per-turn workspace for the chat agent with `write_file`, `read_file`, `list_dir` and `exec_shell`; each command runs in a fresh network-less exec sandbox with exec-quota accounting, files persist between commands, paths are confined to the workspace and symlinks are never kept; lifecycle (destroy at turn end, idle expiry, restart recovery or lost) and idempotent replay by call id.
- **MCP through the Gateway (optional, `--mcp-config`):** stdio and streamable-HTTP MCP servers configured by the operator; only allowlisted tools are exposed (`mcp__<server>__<tool>`), calls are journaled and count against the turn tool budget, credentials stay on the host; demo server `agentbox mcp-demo-server`.
- **Kubernetes provider (`--provider k8s`, opt-in):** each environment runs in one Pod (non-root, read-only root, all capabilities dropped, `RuntimeDefault` seccomp, no service-account token, deny-all NetworkPolicy, optional `runtimeClassName`); the worker image is pinned by digest (tag resolved at startup, `--k8s-image-strict` refuses tags); `--k8s-warm-pool N` keeps pre-started Pods. Passes the provider conformance suite on a fake clientset (CI) and on kind. `scripts/demo-k8s.sh` runs the whole flow on kind. The local provider stays the default.
- **Evaluation platform (`agentbox eval run|report|compare`):** runs a suite of coding/terminal tasks (checked in the exec sandbox by the new `evalworker`) and research questions against a server via the operator API, with concurrency, repetitions and a seed; writes a pinned manifest, trajectory JSONL, graded `summary.json`/`report.md`; compares runs. Optional LLM judge with a hard budget. `fakeupstream -eval-suite` and `scripts/demo-eval.sh` give a zero-cost run. Design: `docs/design/2026-10-10-eval-platform-design.md`.
- **`GET /server-info`** (operator only): build and non-secret configuration, used to pin eval runs.
- **Instant stop:** the stop card appears within seconds even when a model, tool or `run_python` call is in flight; the abandoned call is replayed under the same call id on continue. The stop summary has a 22 s deadline and falls back to a progress-based finding.
- **Host fallback stop card:** when the worker cannot write a stop card (it does not respond in time, or the turn is stopped while still queued) the host writes one with a fixed finding, and continue / write-now still work.
- **"正在停止… N 秒":** the turn shows a ticking stopping row from the moment stop is clicked until the stop card arrives.
- **继续 / continue after a stop** continues the stopped turn instead of starting a new one.
- **Follow-up messages after a stop** always carry the stopped turn's question and progress as context.

- **Dependency security:** the module now targets Go 1.25 (`go 1.25.0`); dependencies that govulncheck reported as reachable were raised to their minimum fixed versions (golang.org/x/net v0.58.0, x/text v0.41.0, OpenTelemetry v1.45.0, gRPC v1.83.1, pgx v5.9.2). Builds and CI use the `toolchain go1.27.2` line (setup-go v6 honours it); with that toolchain govulncheck reports 5 reachable advisories, all HTTP/2 issues in golang.org/x/net that are fixed only in x/net v0.60.0, which requires Go 1.26. CI lint moved to golangci-lint v2 (same linters and thresholds). Raising the go directive from 1.24 to 1.25 changes these GODEBUG defaults for the binaries: `containermaxprocs=1` and `updatemaxprocs=1` (GOMAXPROCS follows the cgroup CPU limit and is updated while running; the runtime keeps the cgroup `cpu.max` file open), `tlssha1=0` (SHA-1 signatures are no longer accepted in TLS 1.2 handshakes), `x509sha256skid=1` (generated certificate SubjectKeyIds use SHA-256), `decoratemappings=1` (anonymous memory mappings are named in /proc/<pid>/maps). Set `GODEBUG` to restore an old default if needed.

- **Review follow-ups (fallback, workspace tools, MCP, Kubernetes):** a hedge whose losing first leg also answered ok no longer counts as a slow failure for that provider's breaker, and a backup's provider fault (wrong key, model or address) no longer turns a retryable call fatal; an MCP server's 5xx to `initialize` is retryable; stdio MCP `uid`/`gid` must be given together; workspace paths reject Unicode control characters and invisible format characters (bidi controls, BOM, soft hyphen, zero-width space; joiners and emoji tags stay allowed, and state files from earlier versions still load); sandbox init checks the types of its inherited fds; a workspace that is only read keeps its idle clock across a restart; the Kubernetes admission policy also covers ephemeral containers (`pods/ephemeralcontainers`) and the remaining Pod Security "restricted" fields (AppArmor, procMount, SELinux, HostProcess, sysctls); a workspace swing interrupted by a crash is merged back at startup; the warm-pool creation backoff is capped at 5 min.
- **Session actor race (CI flake root cause):** a notification that arrived while a session read was in flight was overwritten by the older read result; the actor now re-reads.
- **Cleanup:** `docs/glossary.md` explains the internal references (§, I1–I16, E1–E49, Plan N); `agentbox server` start-up and the attempt create/finalize transactions are split into named steps; the long end-to-end test file is split by area; the web UI has one user-facing error module, shared report styles, and downloads a report once for the chat and the side panel (cleared on sign-out).

## v0.2.0 — 2026-10-07

First public release.

- **Runtime:** Go control plane with task and session state machines, checkpoints and crash recovery, invariant checker, fault injection.
- **Sandbox:** namespaces, mapped UID ranges, read-only rootfs template, seccomp, capabilities `{KILL}`, cgroup v2 limits; separate network-less exec sandbox for model-written Python.
- **Gateway:** per-attempt Unix socket, call journal, task and sub-run budgets, per-turn tool quota (30), SSRF-safe egress, Redis cache and call coalescing.
- **Agent:** Python worker SDK and versioned protocol; chat agent with skills, ask-user, todo list, web search/fetch, `run_python`; parallel sub-runs; challenge / bot-check pages are dropped instead of becoming sources.
- **Product:** accounts (registration passwords 8–16 characters with at least two of digits / upper / lower case), sessions (freeze / evict / restore), chat UI with resizable three-pane layout (progress / sources / report panel, collapsed by default), merged and auto-folded step chain, full report rendered in the conversation with a report card, stop / continue / write-now / restore; operator workbench.
- **Evidence:** real-model acceptance on a 4 vCPU / 8 GiB Linux VM; serial vs. parallel comparison (N = 4 per mode).
