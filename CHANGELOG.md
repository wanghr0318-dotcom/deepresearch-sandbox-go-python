# Changelog

## Unreleased

- **Model provider fallback:** a logical model can be served by an ordered chain of OpenAI-compatible providers (`--model-fallback-file`). Retryable failures (connect error, 429, 5xx, per-try timeout `--model-try-timeout`, empty response) fail over to the next provider immediately; every provider attempt is a journaled try with its own reservation at that provider's price; replay and fingerprints are unchanged. Per-provider circuit breakers (`--model-breaker-failures`, `--model-breaker-open`) skip a dead provider without spending a try; when every provider is open the Gateway answers `503 model_degraded` at once. Optional hedged requests (`--model-hedge-delay`, off by default; a cancelled sent leg is charged its estimate as unknown). `inspect` shows the provider, skipped providers and hedge flag of each try. Without a fallback file behaviour is unchanged. Design: `docs/design/2026-10-10-model-fallback-design.md`; measurements: `docs/evidence/2026-10-10-model-fallback.md`.
- **Observability (off by default):** OpenTelemetry tracing (`--otlp-endpoint`, `--trace-sample-ratio`) with one trace per user action from the API request through the task actor, attempts, worker start/handshake/checkpoints and into the sandbox — the worker forwards the W3C `traceparent` it receives in `init` / `task_start` to every Gateway call, which the Gateway accepts only within the attempt's own trace; Prometheus `/metrics` on a separate operator-only listener (`--metrics-listen`): task/turn verdicts, attempt ready, submit→ready and stop latency, upstream try latency and errors by provider/model/status, Gateway call results, cost in micro-USD, tool calls per task, sandbox environments, cleanup backlog, run/exec slots; JSON logs carry `trace_id`/`span_id` and can also be written to a file (`--log-file`). `deploy/observability` (OTel Collector, Tempo, Prometheus, Loki + Alloy, Grafana with a provisioned dashboard) and `scripts/demo-observability.sh`.

- **Workspace tools (optional, `--workspace-tools`):** a per-turn workspace for the chat agent with `write_file`, `read_file`, `list_dir` and `exec_shell`; each command runs in a fresh network-less exec sandbox with exec-quota accounting, files persist between commands, paths are confined to the workspace and symlinks are never kept; lifecycle (destroy at turn end, idle expiry, restart recovery or lost) and idempotent replay by call id.
- **MCP through the Gateway (optional, `--mcp-config`):** stdio and streamable-HTTP MCP servers configured by the operator; only allowlisted tools are exposed (`mcp__<server>__<tool>`), calls are journaled and count against the turn tool budget, credentials stay on the host; demo server `agentbox mcp-demo-server`.
- **Kubernetes provider (`--provider k8s`, opt-in):** each environment runs in one Pod (non-root, read-only root, all capabilities dropped, `RuntimeDefault` seccomp, no service-account token, deny-all NetworkPolicy, optional `runtimeClassName`); the worker image is pinned by digest (tag resolved at startup, `--k8s-image-strict` refuses tags); `--k8s-warm-pool N` keeps pre-started Pods. Passes the provider conformance suite on a fake clientset (CI) and on kind. `scripts/demo-k8s.sh` runs the whole flow on kind. The local provider stays the default.
- **Evaluation platform (`agentbox eval run|report|compare`):** runs a suite of coding/terminal tasks (checked in the exec sandbox by the new `evalworker`) and research questions against a server via the operator API, with concurrency, repetitions and a seed; writes a pinned manifest, trajectory JSONL, graded `summary.json`/`report.md`; compares runs. Optional LLM judge with a hard budget. `fakeupstream -eval-suite` and `scripts/demo-eval.sh` give a zero-cost run. Design: `docs/design/2026-10-10-eval-platform-design.md`.
- **`GET /server-info`** (operator only): build and non-secret configuration, used to pin eval runs.
- **Instant stop:** the stop card appears within seconds even when a model, tool or `run_python` call is in flight; the abandoned call is replayed under the same call id on continue. The stop summary has a 22 s deadline and falls back to a progress-based finding.
- **Host fallback stop card:** when the worker cannot write a stop card (it does not respond in time, or the turn is stopped while still queued) the host writes one with a fixed finding, and continue / write-now still work.
- **"正在停止… N 秒":** the turn shows a ticking stopping row from the moment stop is clicked until the stop card arrives.
- **继续 / continue after a stop** continues the stopped turn instead of starting a new one.
- **Follow-up messages after a stop** always carry the stopped turn's question and progress as context.

- **Dependency security:** the module now targets Go 1.25 (`go 1.25.0`); dependencies that govulncheck reported as reachable were raised to their minimum fixed versions (golang.org/x/net v0.58.0, x/text v0.41.0, OpenTelemetry v1.45.0, gRPC v1.83.1, pgx v5.9.2). The remaining x/net HTTP/2 advisories are fixed only in x/net v0.60.0, which requires Go 1.26. CI lint moved to golangci-lint v2 (same linters and thresholds).

## v0.2.0 — 2026-10-07

First public release.

- **Runtime:** Go control plane with task and session state machines, checkpoints and crash recovery, invariant checker, fault injection.
- **Sandbox:** namespaces, mapped UID ranges, read-only rootfs template, seccomp, capabilities `{KILL}`, cgroup v2 limits; separate network-less exec sandbox for model-written Python.
- **Gateway:** per-attempt Unix socket, call journal, task and sub-run budgets, per-turn tool quota (30), SSRF-safe egress, Redis cache and call coalescing.
- **Agent:** Python worker SDK and versioned protocol; chat agent with skills, ask-user, todo list, web search/fetch, `run_python`; parallel sub-runs; challenge / bot-check pages are dropped instead of becoming sources.
- **Product:** accounts (registration passwords 8–16 characters with at least two of digits / upper / lower case), sessions (freeze / evict / restore), chat UI with resizable three-pane layout (progress / sources / report panel, collapsed by default), merged and auto-folded step chain, full report rendered in the conversation with a report card, stop / continue / write-now / restore; operator workbench.
- **Evidence:** real-model acceptance on a 4 vCPU / 8 GiB Linux VM; serial vs. parallel comparison (N = 4 per mode).
